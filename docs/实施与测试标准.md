# 实施与测试标准

## 排期建议

前端1人、Java1人、测试1人及CMP5对接人配合，环境就绪后预计6～8周，不包含等待接口/微信审核时间。

| 阶段 | 时间 | 成果 |
|---|---|---|
| 流程/原型确认 | 第1周 | 页面、角色矩阵、状态及异常路径 |
| 工程和接口契约 | 第2周 | 登录框架、Mock、BFF骨架、OSS方案 |
| 订货收货 | 第3～4周 | CMP5字段映射、入账和重复提交验证 |
| 差异退货 | 第4～5周 | 审批、库存占用、异常和追踪 |
| 联调回归 | 第6周 | 真实接口测试、权限和库存一致性 |
| 试点上线 | 第7～8周 | 真机、门店试点、监控和回滚 |

当前交付覆盖界面及模拟流程，不代表上述真实系统工作全部完成。Java服务、真实CMP5/OSS、服务端分页、批次/效期、分批收货、错货/超收、私有附件及生产权限仍待实施。

## 自动化验证

`npm test`：覆盖密码校验、会话持久化/退出撤销、并发刷新、退出刷新竞争、网络错误、401重试上限、业务流程、包装倍数、收货回滚、幂等、重复收货、退货并发占用和门店隔离。

`npm run build:mp-weixin`：验证所有Vue页面可编译为微信原生小程序产物。编译通过不等于微信真机验收。

`npm run check:release`：检查真实AppID、非Mock模式、HTTPS API/OSS配置；当前演示版本应失败，这是预期结果。

## 微信开发者工具及真机验收清单

- [ ] 输入错误密码得到提示，连续错误触发限流；正确凭证可登录。
- [ ] 关闭重开保持会话，退出后不能进入业务页面，密码不写入Storage。
- [ ] 小屏320/375宽、常见390/430宽下无横向溢出，底部按钮不遮挡内容。
- [ ] 真机iOS/Android数量键盘、密码输入、长名称、下拉刷新、返回导航正常。
- [ ] 订货最小量与倍数有效；重复点击不创建重复单据。
- [ ] 审核前可取消；审核后不显示不允许的操作。
- [ ] 收货数量合法，超收被阻止，短收/破损说明必填。
- [ ] 差异来源可追溯，核对结果明确显示。
- [ ] 退货不超可退数量，未批准不能出库；取消释放占用。
- [ ] 断网、超时、会话过期和版本冲突提供可理解的提示。
- [ ] OSS失效时仍有占位；真实私有附件不能匿名访问。

## 正式上线门槛

1. 真实API合同、权限矩阵和状态流评审通过，核心业务用例全部通过。
2. 收货/退货库存及金额和CMP5一致，重复提交与结果不明具备恢复机制。
3. 用户不能通过更改门店或单据ID访问他店；演示接口不在生产后端开放。
4. 无阻断或高严重度业务缺陷；依赖漏洞经影响分析处理，不能直接用 `npm audit fix --force` 破坏 uni-app 版本匹配。
5. 微信开发者工具预览及iOS/Android真机通过；平台主体、类目、隐私指引按真实业务补齐。
6. 试点门店确认、告警和追踪可用，发布及回滚责任人明确。

## 部署和回滚

每次发布保留源码版本、lockfile、AppID、构建环境、接口配置版本和构建包。先发内部体验版验证，再提审。BFF采用兼容旧客户端的接口版本；不能假设所有终端即时更新。发现问题时按微信平台能力回退客户端并回滚服务配置；已产生的库存业务通过CMP5冲销或补偿处理，不能删除数据库记录伪造回滚。

# 架构与接口规范

## 当前交付与边界

当前是微信小程序界面及业务流程体验工程，使用 Vue 3、uni-app、统一 CSS 设计体系。页面通过 `services/api.js` 访问数据，禁止页面直接调用 CMP5。演示数据与待接入的远程接口共享当前前端契约。

正式结构建议：微信小程序 → HTTPS Java BFF → CMP5；图片从阿里云 OSS 获取。BFF 管理身份、签名、权限、幂等、审计，不重复实现 CMP5 库存账和审批。

**结论：推荐 Java BFF。** 若企业已有提供相同能力的 API 网关/BFF，则复用；只有 CMP5 已具备面向小程序的安全认证、完整权限和无客户端共享密钥方案时，才评估直连。当前仓库不包含 Java 后端，不能将远程模式直接指向未知 CMP5 API 后认为可用。

## Java BFF 实施方案

- Spring Boot + 企业受支持的 JDK，版本在后端立项时锁定；用 Redis 维护会话、限流和短期幂等状态，数据库记录操作审计与外部流水。
- `AuthController / SessionService`：对接 CMP5 身份系统或企业统一认证，签发短期访问令牌与轮换刷新令牌，服务端撤销会话。
- `StoreAuthorizationService`：验证用户、门店、动作、来源单归属，客户端门店参数不是授权依据。
- `CmpClient / CmpSigner / CmpMapper`：固定地址和接口白名单，按真实文档实现签名与字段映射，禁止用户提供任意上游 URL。
- `OrderService / ReceiptService / DifferenceService / ReturnService`：编排 CMP5 调用，保留原始单号、状态与追踪编号。
- `IdempotencyService`：键作用域为用户/门店/动作，记录请求摘要、进行中/成功/结果不明状态。同键不同报文拒绝；结果不明先查 CMP5，再由补偿任务恢复。
- CMP5 若缺少外部流水查询/幂等能力，仅 BFF 加锁不能保证跨系统恰好一次，需业务对账与人工异常队列。
- 配置通过环境/密钥服务注入，区分测试生产；日志脱敏，不记录密码、完整令牌和签名密钥。配置热更新应有版本、审批和回滚。
- 提供超时、有限熔断、traceId、错误率、上游耗时及异常流水告警；写请求不得自动盲重试。

## 环境

复制 `.env.example` 为 `.env.local`（不会进入版本管理）：

```dotenv
VITE_API_MODE=remote
VITE_API_BASE_URL=https://实际BFF域名/api/v1
VITE_OSS_BASE_URL=https://实际图片域名
```

默认 `mock`；接口失败不会自动降级至 mock。所有 VITE_ 变量会进入前端包，不能填写 CMP5 密钥、AppSecret 或 OSS AccessKey。改变变量后必须重新构建。

当前 remote 分支是待联调的前端契约，后端未部署。签名与实际字段对接须等待 CMP5 文档。

## HTTP 约定

统一成功响应：

```json
{"code":"OK","message":"成功","data":{},"traceId":"服务端追踪编号"}
```

失败响应使用非2xx状态：

```json
{"code":"VERSION_CONFLICT","message":"单据已更新，请重新加载","data":null,"traceId":"服务端追踪编号"}
```

401：会话无效；403：无权限；404：单据不存在；409：版本/幂等冲突；422：业务参数不合法；429：限流；502/504：上游故障或超时。

请求头：`Authorization: Bearer <accessToken>`、`X-Store-Id`。POST 写操作附带 `Idempotency-Key`；同一次操作的失败重试沿用该键，不同参数使用新键。

所有单据有 `id/storeId/status/version/createdAt/lines/history`。SKU、来源单据号由服务端验证。数量在当前演示中为非负整数，订货/退货必须大于0，最大99999；称重品/小数单位、批号、效期需要真实接口确定后扩展。金额按分计算，价格以服务端为准。时间是 ISO8601 UTC，界面转换为设备本地时间。

## 会话与并发

访问令牌临近过期30秒时刷新；并发请求复用同一刷新任务，401最多重试一次。网络错误不清理有效刷新令牌。会话修订号阻止退出后晚返回的请求或刷新恢复旧会话。令牌保存在 uni storage，密码不落盘。

演示令牌不是安全令牌，演示凭证和本机鉴权不能用于生产；真实后端需实现密码策略、限流、刷新轮换、重放检测、门店隔离及审计。多账号/多门店需扩展缓存命名空间和授权选择界面，当前仅单门店演示。

## 单据状态与业务规则

- 订货：DRAFT → SUBMITTED → APPROVED；订货仅草稿可 CANCELLED，提交后不可编辑或取消。提交后模拟批准生成配送单，实际审批与发货应以 CMP5 两个事件为准。
- 收货：PENDING → RECEIVED；按配送数量核对，合格+破损不得超过发货；存在差异必须说明。当前一次性确认，不支持分批收货、超收或错货入账。
- 差异：OPEN → RESOLVED，来源为收货的短收/破损。当前仅记录核对意见；真实方案需补充 CMP5 处理结果、门店确认、补发/索赔状态及附件。
- 退货：DRAFT → SUBMITTED → APPROVED → SHIPPED → COMPLETED；待审可 REJECTED，草稿/待审可 CANCELLED。已提交/批准/出库/完成的退货均占用来源可退数量；提交时重新校验，防止多个草稿同时超退。
- 演示事务先完整校验再提交，校验失败回滚；真实事务与库存必须由后台处理。
- 订货暂存单可从详情进入编辑，更新原单据而非生成新单；退货草稿仍通过取消后重建，退货驳回后从原收货单重新申请。

## OSS

固定商品图片统一从 `${VITE_OSS_BASE_URL}/miniapp/v1/products/{sku}.png` 访问；当前六个SKU为 DD1001～DD1006。未配置域名或图片失败时使用 CSS/文字占位，不依赖第三方外链图片。

资源目录采用版本化路径和缓存；公开品牌/商品图与私有差异凭证分开。私有附件需后端授权、短期签名、文件类型和大小校验、归属校验；当前未实现附件上传。小程序按实际使用 API 配置 request/download/upload 合法域名并保持 HTTPS。

当前没有真实 OSS 域名及上传授权，未上传任何图片到云端。

## CMP5 联调前必须补齐

认证和签名规范、测试地址、超时和限流要求、组织与门店编码、商品/单位/价格字段、来源单据关系、审批状态、收货库存生效时点、差异处理规则、退货限额和占用、幂等或流水查询、附件和审计规则。用已脱敏的真实报文建立契约测试后再切换 remote。

## 新建订货交互（2026-10-11）

第一步展示登录账号的当前门店（不可任意改写门店）及可用订货模板，未选择模板不可继续。第二步展示模板名称、商品搜索、左侧动态品类导航和右侧商品数量输入；分类来自模板商品，不写死在页面。保存草稿携带 templateId，详情保留 templateId/templateName。后端必须验证模板启用状态、门店适用范围及商品归属，模板停用或商品移除时拒绝保存并提示刷新。当前演示预置日常补货、乳品饮料、烘焙零食三种模板，真实模板需由 CMP5 或 BFF 提供。

未保存输入按门店与模板分别缓存，切换模板不混用；旧版本输入仅迁移至日常补货演示模板。保存成功仅清除该模板输入，退出登录清除该门店全部输入。数量校验、幂等及提交审核流程沿用原规则。模板字段映射、有效期和可用商品范围待 CMP5 文档确认。

商品页右上角提供到货日期选择（arrivalDate，YYYY-MM-DD，本地日历日期），默认今天，允许今天及以后；随模板输入缓存，并在订货详情展示。过去日期或无效日期拒绝保存；旧缓存的过期日期重置为今天。演示接口兼容旧调用不传该字段，正式 CMP5 日期窗口、截单时点及配送排程规则待联调确定，界面选择属于期望到货日期。商品数量初始化为0，旧空值迁移为0，清空后失焦恢复0；数量0不加入订货行。

## 单据查询和暂存编辑（2026-10-12）

保留单据卡片和新建按钮布局。订货状态查询：ALL（全部）、DRAFT（暂存）、SUBMITTED（已提交，包含后台SUBMITTED和APPROVED），界面不显示待审核。后台审批流程不删除；已取消单据在全部状态可查，单独状态查询仅提供暂存/已提交。其他业务模块保留各自实际状态，所有单据列表增加创建日期查询。

GET /{kind} 新增 status、fromDate、toDate、search 参数。日期是YYYY-MM-DD，按门店本地创建日期包含起止日；默认今天及前六天，选项今天、昨天、近七天、本月、近三月（本月及前两个月）。日期和状态更改立即查询，搜索防抖300ms，过滤在演示服务端执行。未传参数的旧GET仍兼容。真实BFF应按门店时区处理范围，实施授权与服务端分页。

POST /orders/{id}/update：version、templateId、arrivalDate、lines:[{sku,quantity}]、remark，返回原单据并递增version。只允许DRAFT，校验门店归属、版本、模板、商品范围、包装倍数及日期；更换模板拒绝，失败原子回滚，使用Idempotency-Key。已提交拒绝修改和取消，详情无编辑入口，直接打开编辑URL也会被状态校验阻止。草稿编辑输入按单号单独缓存并记录基础版本，版本不同不恢复旧输入；退出登录清除输入。若旧到货日期早于今天，需重新选择后保存。旧演示草稿无模板ID时迁移到日常模板；生产迁移需依据CMP真实来源字段。

真实CMP5/BFF尚待部署，必须提供同等更新与查询接口、数据库事务和权限校验，前端隐藏按钮不能替代后台校验。
